# 🧠 My AI Rules & Setup

This is where I keep all my instructions and rules for building stuff with AI. It's tailored to exactly how I like to code—clean, fast, and looking great.

## 🚀 The Point
I use this repo to make sure the AI knows exactly what I want: apps that look premium, work perfectly for everyone, and follow my specific coding style.

## 📁 What's inside?

### 🛠️ The Rules (`rules/`)
These are the core guidelines the AI follows while we work:
- **`code-review.mdc`**: A checklist for catching bugs and making sure the code is solid. It even checks documentation and other code on GitHub.
- **`web-guidelines.mdc`**: How I want the UI/UX to feel. Think smooth animations and accessibility.
- **`ultracite.mdc`**: The "boring" stuff—formatting and linting so the code stays clean.
- **`ui-skills.mdc`**: Tricks for making things look fancy.

### ⌨️ Commands (`commands/`)
Quick scripts to get things done:
- **`teach-impeccable`**: Teaches the AI about the project's design vibe.
- **`audit`, `polish`, `simplify`**: Simple commands to fix or clean up the code.

### 🎨 Design (`frontend-design/`)
Reference stuff for the design system so everything looks consistent.

## ⚖️ How I Roll
This setup is biased. I care about:
- **Looking Good**: It has to WOW people. Gradients, dark mode, the works.
- **Easy to Use**: Needs to work for everyone (accessibility matters).
- **Learning**: I want the AI to explain *why* it's doing things, not just do them.
- **Consistency**: Keep it simple and follow the patterns we've already set.
